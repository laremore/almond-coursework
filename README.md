## Задача

Классификация изображений миндаля на 4 сорта: **Ak**, **Nurlu**, **Sıra**, **Kapadokya**.

Метрики: основная — accuracy на валидационной и тестовой выборках; дополнительные — precision, recall, F1-score по классам (macro и weighted average).

## Данные

**Источник:** Almond Varieties Dataset (Kaggle).
Ссылка: https://www.kaggle.com/datasets/mahyeks/almond-varieties

**Состав:** 1556 изображений, 4 класса (Ak, Nurlu, Sıra, Kapadokya).

**Разбиение:** 70% / 15% / 15% (train / val / test) с фиксированным seed (`torch.Generator().manual_seed(42)`) для воспроизводимости. Пересечения и дубликаты между выборками исключены, так как разбиение выполняется по индексам исходного датасета.

**Аугментация (только train):** RandomResizedCrop(224), RandomHorizontalFlip, нормализация по статистикам ImageNet. Для val/test — Resize(256) + CenterCrop(224) + нормализация.

**Структура каталога с данными:**

```
data/
└── almond/
    ├── Ak/
    ├── Nurlu/
    ├── Sıra/
    └── Kapadokya/
```

## Модель и модификация

**Базовая архитектура:** ResNet18, предобученная на ImageNet (`ResNet18_Weights.DEFAULT`), с заменой полносвязного слоя под 4 класса.

**Модификация (уровень 4) — замена функции потерь на Focal Loss:**

```
FL(p_t) = -alpha * (1 - p_t)^gamma * log(p_t)
```

Параметры: `gamma = 2.0`, `alpha = 1.0`.

**Цель модификации:** снизить вклад простых примеров в функцию потерь и сфокусировать обучение на сложных, что должно повысить устойчивость модели при малом размере датасета и высокой дисперсии валидационной метрики.

Дополнительно был обучен вариант с архитектурной модификацией **CBAM** (блоки внимания после Stage 2–4 ResNet18) — для сравнения. CBAM прироста не дал (см. раздел «Эксперименты»).

## Эксперименты

Все три варианта обучены на одной обучающей выборке с одинаковыми гиперпараметрами:

| Параметр | Значение |
|---|---|
| Эпохи | 20 |
| Optimizer | Adam |
| Learning rate | 0.001 |
| Batch size | 32 |
| Функция потерь (базовая) | CrossEntropyLoss |
| Вход | 224×224 |

Результаты на валидационной выборке:

| Модель | Best Val Acc | Val Loss (эпоха 20) |
|---|---|---|
| ResNet18 + CrossEntropy (базовая) | 93.56% | 0.3722 |
| ResNet18 + CBAM | 92.70% | 0.4528 |
| **ResNet18 + Focal Loss** | **95.28%** | **0.0747** |

**Вывод:** Focal Loss дал прирост +1.72 п.п. к валидационной точности относительно базовой модели и снизил val loss примерно в 5 раз. CBAM прироста не дал — вероятная причина: малый размер датасета и высокая дисперсия валидационной метрики. Финальная модель — **ResNet18 + Focal Loss**.

Все запуски зафиксированы в трекере ClearML (см. раздел «Трекер экспериментов»).

## Запуск обучения

1. Скачай датасет с Kaggle и распакуй в `data/almond/` так, чтобы получилась структура из раздела «Данные».

2. Подготовь доступ к ClearML: зарегистрируйся на https://app.clear.ml, создай credentials (Settings → Workspace → Create new credentials), выполни в терминале на хосте:

```bash
clearml-init
```

и вставь скопированную конфигурацию. Ключи также можно передать через переменные окружения `CLEARML_API_ACCESS_KEY` и `CLEARML_API_SECRET_KEY` (см. `docker-compose.yml`).

3. Запусти обучение в контейнере:

```bash
docker-compose run train
```

По умолчанию обучается модель, заданная в `src/train.py` (`EXPERIMENT_NAME` и `USE_CBAM`). Для воспроизведения всех трёх экспериментов последовательно меняй эти две переменные:

| Эксперимент | `EXPERIMENT_NAME` | `USE_CBAM` | Функция потерь |
|---|---|---|---|
| Базовая | `resnet18_base_almond` | `False` | CrossEntropyLoss |
| CBAM | `resnet18_cbam_almond` | `True` | CrossEntropyLoss |
| Focal Loss | `resnet18_focal_almond` | `False` | FocalLoss(gamma=2.0) |

Веса лучшей эпохи сохраняются в файл `best_<EXPERIMENT_NAME>.pth` в корне проекта (каталог подключён томом, поэтому файлы остаются на хосте после удаления контейнера).

4. Оценка на тестовой выборке:

```bash
python -m src.evaluate
```

(или внутри контейнера обучения). В `src/evaluate.py` укажи путь к весам финальной модели.

## Запуск микросервиса

Сервис запускается с готовыми весами, **без повторного обучения**:

```bash
docker-compose up --build service
```

Сервис будет доступен на `http://localhost:8000`.

Проверка готовности:

```bash
curl http://localhost:8000/health
```

Ожидаемый ответ: `{"status":"ok"}`. Успешный ответ возвращается только после загрузки модели.

Остановить:

```bash
docker-compose down
```

## API

### GET /health

Проверка готовности сервиса. Возвращает `200` и `{"status":"ok"}`, если модель загружена, иначе `503`.

### POST /predict

Принимает изображение в формате `multipart/form-data`, поле `file`.

**Пример запроса (Windows PowerShell):**

```powershell
curl.exe -X POST -F "file=@data/almond/Ak/test.jpg" http://localhost:8000/predict
```

**Пример запроса (Linux/macOS):**

```bash
curl -X POST -F "file=@data/almond/Ak/test.jpg" http://localhost:8000/predict
```

**Пример ответа:**

```json
{
  "class": "Ak",
  "probabilities": {
    "Ak": 0.923977792263031,
    "Nurlu": 0.07598567754030228,
    "Sıra": 0.000010179085620620754,
    "Kapadokya": 0.000026318673917558044
  }
}
```

Поля ответа:
- `class` — предсказанный сорт (строка);
- `probabilities` — словарь «класс → вероятность» (сумма вероятностей равна 1).

**Ошибки:**
- `400` — файл не является изображением или не может быть прочитан (`{"detail": "..."}`);
- `503` — модель ещё не загружена.

## Результаты

**Тестовая выборка (234 изображения), финальная модель ResNet18 + Focal Loss:**

```
Test Accuracy: 93.59%

              precision    recall  f1-score   support

          AK       1.00      0.90      0.95        68
   KAPADOKYA       0.91      0.92      0.91        73
       NURLU       0.86      0.95      0.90        40
        SIRA       0.96      1.00      0.98        53

    accuracy                           0.94       234
   macro avg       0.93      0.94      0.94       234
weighted avg       0.94      0.94       0.94       234
```

**Анализ ошибок:** основной источник ошибок — смешение классов **AK** и **NURLU** (precision NURLU 0.86, recall AK 0.90). Вероятная причина — визуальное сходство текстуры скорлупы и малое число примеров NURLU в тестовой выборке (40 изображений). Классы Sıra и Kapadokya распознаются практически безошибочно (F1 0.98 и 0.91 соответственно).

**Ограничения:** малый размер датасета (1556 изображений) приводит к заметным колебаниям валидационной метрики между эпохами; результат чувствителен к выбранному разбиению. Для повышения устойчивости имеет смысл кросс-валидация или увеличение датасета.
